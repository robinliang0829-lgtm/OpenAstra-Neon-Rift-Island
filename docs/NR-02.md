# NR-02 规则

给游戏组-虚幻引擎操作。这张卡只有一个要验收的动作。

**验证动作：** 开两个都能独立输入的客户端，打出一份与 `sim/steel_tide` 一致的事件日志：同帧抢一枚芯只有一人拿住，读条被击中则不计分，芯坠海或卡住满 8 秒回到中场；掉在地上的芯还能被再次拾起并完成一次未被打断的得分。

**通过：** 两个视角加上同一份服务器事件日志。日志里同时有 `CorePicked` 与 `CorePickRejected`（`already_held`）、`ScoreChannelInterrupted` 且该次没有 `PointScored`、`CoreReset` 回到 `NR_CoreSpawn`，以及另一次真正的 `PointScored` + `CoreReturnedToCenter`。持有者全程只有一个。最终比分和日志一致。

**出现双持或同一次读条记两分：** 保留现场，把两端日志退回 Codex。不要改胜负条件，也不要在 Notion 上冻结新规则。

**模块还不在工程里时的唯一合法结果：** 只摆下面的体积，截图，回传 `BLOCKED native rules module not in this build`，并附上 `PYTHONPATH=sim python3 -m steel_tide repro` 的输出作为期望日志。不要用关卡蓝图写第二套计分来换一张「通过」。

## 输入

- 与 NR-01 同一工程、同一关卡 `NR_SteelTide_Greybox`、同一 Git SHA
- 接线说明：`docs/rules/UE_EVENT_WIRING.md`
- 参数：`config/steel_tide_greybox.json`
- 期望日志：`PYTHONPATH=sim python3 -m steel_tide repro`

## 目标对象

在 NR-01 的灰盒上增加，不要改已量过的距离：

| 对象 | 位置 | 行为 |
| --- | --- | --- |
| `NR_Core` | 开始时放在 `NR_CoreSpawn` | 全场只有这一枚 |
| `NR_CorePickup` | 中心，半径 150 uu（1.5 米） | 重叠且按下交互 → 服务器 `pick_core` |
| `NR_Terminal_A` 体积 | 半边 200 uu | B 的持芯者在此 `begin_score`；End Overlap → 服务器 `leave_terminal` |
| `NR_Terminal_B` 体积 | 半边 200 uu | A 的持芯者在此读条 |
| `NR_SeaVolume` | 锚点 sea，UE (4800, -3000, 0) | 服务器 `mark_core_overboard` |
| `NR_StuckVolume` | 锚点 stuck，UE (4800, -800, 0) | 服务器 `mark_core_stuck` |

`NR_SeaWall` 仍然挡住平时行走。测复位时，用调试命令或把芯丢进 `NR_SeaVolume`，不要拆掉海堤。

## 参数

全部来自配置，不要在蓝图默认值里再写一遍：

- 读条 3.0 秒。受击或离开体积清掉进度，停留但没有新的 `begin_score` 不会自己补上这一分
- 坠海 / 卡住 8.0 秒后 `CoreReset`。复位不计分
- 得分后是 `CoreReturnedToCenter`，芯回中场，可以再被拾取
- 倒地 5.0 秒后回本方 `NR_Spawn_*`，出生保护 3.0 秒。芯留在掉落点
- 同帧两名客户端一起交互时，服务器按接线文档的排序只授予一人

两人使用同一套人形机器人网格，本局分别选 A 和 B。队标用肩章形状，不要靠脸或只靠颜色。这一卡先确认事件，肩章的色盲可读性在 NR-03。

## 步骤

1. 确认工程里有没有 `UNeonRiftMatchSubsystem`。没有就停在「模块还不在」那一档，摆好体积后回传 BLOCKED。
2. 有模块时，把上表体积接到接线文档里的意图上。服务器权威，客户端只发意图。
3. PIE 两个独立输入的客户端。条件允许时再用同网段两台机器；这次可以先同机双进程。回传里写明是哪一种。
4. 两人站上 `NR_Core`，同一帧交互。确认只有一人 `CorePicked`。
5. 持芯者到对方端子读条，在满 3 秒前由服务器造成一次命中。确认打断、掉芯、不计分，倒地者会复活，另一人可以捡起地上的芯。
6. 再完成一次不被打断的 3 秒读条。确认只加 1 分，芯回中场。
7. 把芯送进 `NR_SeaVolume`（或 `NR_StuckVolume`）。8 秒内不能拾取；到时芯出现在 `NR_CoreSpawn`，比分不变。

## 画面目标

两个窗口都能看出谁拿着芯、芯掉在哪、比分是多少。打断的那一次，读条 UI 归零且比分不动。复位后中场只有一枚芯。

## 回传

卡号 NR-02；构建标识；引擎小版本；机器；实际步骤；两端录像路径；事件日志路径；最终持有者与比分。日志用接线文档的一行一条格式。失败时留下原关卡和两端视角。
