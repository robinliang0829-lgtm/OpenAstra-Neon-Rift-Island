# NR-02 规则

给游戏组-虚幻引擎操作。这张卡只有一个要验收的动作。

**仓内准备已齐。Only local UE is missing.** 还缺的只有本机 UE。双端日志格式、3v3 样例和只订阅不记分的 GameMode / GameState / PlayerState 都在这个 Git 里。本环境没有 UE，编辑器没有打开过工程。装上本机引擎之后按文末「上机后对日志」收三份日志。不要在关卡蓝图里写第二套计分。

**验证动作：** 开两个都能独立输入的客户端，打出一份与 `sim/steel_tide` 一致的事件日志：同帧抢一枚芯只有一人拿住，读条被击中则不计分，芯坠海或卡住满 8 秒回到中场；掉在地上的芯还能被再次拾起并完成一次未被打断的得分。

**通过：** 两个视角加上同一份服务器事件日志。日志里同时有 `CorePicked` 与 `CorePickRejected`（`already_held`）、`ScoreChannelInterrupted` 且该次没有 `PointScored`、`CoreReset` 回到 `NR_CoreSpawn`，以及另一次真正的 `PointScored` + `CoreReturnedToCenter`。持有者全程只有一个。最终比分和日志一致。

**出现双持或同一次读条记两分：** 保留现场，把两端日志退回 Codex。不要改胜负条件，也不要在 Notion 上冻结新规则。

**计分还在 Python 原型里。** `Source/NeonRift` 的 GameMode / GameState / PlayerState 只订阅并广播 `NeonRiftEventNames.h` 里的名字，不裁定持有者，也不在本地加分。没有本机 UE 时，把缺的引擎路径回给 PM-钢潮岛。不要用关卡蓝图写第二套计分来换一张「通过」。双端参照是 `PYTHONPATH=sim python3 -m steel_tide nr02 --check`。`repro` 仍是原先四条脚本复现。

## 输入

- 与 NR-01 同一工程、同一关卡 `NR_SteelTide_Greybox`、同一 Git SHA
- 接线说明：`docs/rules/UE_EVENT_WIRING.md`
- 双端日志格式：`docs/rules/DUAL_END_EVENT_LOG.md`
- 参数：`config/steel_tide_greybox.json`
- 期望日志：`PYTHONPATH=sim python3 -m steel_tide nr02 --check`
- 样例：`docs/evidence/nr02/server.log`、`client-a.log`、`client-b.log`

## 目标对象

在 NR-01 的灰盒上增加，不要改已量过的距离：

| 对象 | 位置 | 行为 |
| --- | --- | --- |
| `NR_Core` | 开始时放在 `NR_CoreSpawn` | 全场只有这一枚 |
| `NR_CorePickup` | 中心，半径 150 uu（1.5 米） | 重叠且按下交互 → 服务器 `pick_core` |
| `NR_Terminal_A` 体积 | 半边 200 uu | B 的持芯者在此 `begin_score`；End Overlap → 服务器 `leave_terminal` |
| `NR_Terminal_B` 体积 | 半边 200 uu | A 的持芯者在此读条 |
| `NR_SeaVolume` | 锚点 sea，UE (4800, -3000, 0) | 服务器 `mark_core_overboard` |
| `NR_StuckVolume` | 锚点 stuck，UE (4800, -800, 0) | 服务器 `mark_core_stuck` |

`NR_SeaWall` 仍然挡住平时行走。测复位时，用调试命令或把芯丢进 `NR_SeaVolume`，不要拆掉海堤。

## 参数

全部来自配置，不要在蓝图默认值里再写一遍：

- 读条 3.0 秒。受击或离开体积清掉进度，停留但没有新的 `begin_score` 不会自己补上这一分
- 坠海 / 卡住 8.0 秒后 `CoreReset`。复位不计分
- 得分后是 `CoreReturnedToCenter`，芯回中场，可以再被拾取
- 倒地 5.0 秒后回本方 `NR_Spawn_*`，出生保护 3.0 秒。芯留在掉落点
- 同帧两名客户端一起交互时，服务器按接线文档的排序只授予一人

两人使用同一套人形机器人网格，本局分别选 A 和 B。队标用肩章形状，不要靠脸或只靠颜色。这一卡先确认事件，肩章的色盲可读性在 NR-03。

## 步骤

1. 打开同一份 `NeonRift.uproject`。体积接到 `docs/rules/UE_EVENT_WIRING.md`。服务器权威，客户端只发意图。`Emit*` 只是广播，不是已经算完的胜负。
2. 本机没有 UE 时停止，并把缺的安装路径回给 PM-钢潮岛。规则侧不用再等。Only local UE is missing.
3. PIE 两个独立输入的客户端。条件允许时再用同网段两台机器；这次可以先同机双进程。回传里写明是哪一种。
4. 两人站上 `NR_Core`，同一帧交互。确认只有一人 `CorePicked`。
5. 持芯者到对方端子读条，在满 3 秒前由服务器造成一次命中。确认打断、掉芯、不计分，倒地者会复活，另一人可以捡起地上的芯。
6. 再完成一次不被打断的 3 秒读条。确认只加 1 分，芯回中场。
7. 把芯送进 `NR_SeaVolume`（或 `NR_StuckVolume`）。8 秒内不能拾取；到时芯出现在 `NR_CoreSpawn`，比分不变。

## 画面目标

两个窗口都能看出谁拿着芯、芯掉在哪、比分是多少。打断的那一次，读条 UI 归零且比分不动。复位后中场只有一枚芯。

## 回传

卡号 NR-02；构建标识；引擎小版本；机器；实际步骤；两端录像路径；事件日志路径；最终持有者与比分。日志用 `docs/rules/DUAL_END_EVENT_LOG.md` 的一行一条格式。失败时留下原关卡和两端视角。

## 上机后对日志

仓内命令（仓库根目录）：

```bash
PYTHONPATH=sim python3 -m steel_tide nr02
PYTHONPATH=sim python3 -m steel_tide nr02 --check
```

`--check` 必须先通过。它跑 3v3：人类视角 `client-a` / `a1` 与 `client-b` / `b1`，本地 bot `a2`、`a3`、`b2`、`b3`。样例三份日志的事件正文逐字相同，表头标出各自视角。比分镜像是 `A=1 B=0`。这是参照，不是第二套胜负。

装上本机 UE 之后：

1. 打开 `NeonRift.uproject`。允许编译。`EngineAssociation` 仍是 `5.4` 占位。小版本不一致就停，把安装路径回给 PM-钢潮岛，不要自己改工程。
2. 按 [HANDOFF](HANDOFF.md) 把灰盒补齐（若这台机器还没有那张关卡）。不要交回 `.umap` / `.uasset`。
3. PIE 两个独立输入的客户端。`SetViewpointClientId` 分别设为 `client-a` 和 `client-b`。条件允许再换同网段两台机器，回传里写明是哪一种。
4. 走完上面的步骤 4 到 7：同帧抢芯、打断、掉落后再得分、海水或卡住满 8 秒复位。
5. 服务器保存 `ANeonRiftGameState` 的 `AuthoritativeEventLog`。每个客户端保存自己 `ANeonRiftPlayerState` 的 `ViewpointEventLog`。按 schema 加上表头。存根行是 `EventName  {json}`；有权威毫秒时用样例的 `t_s  EventName  {json}`。
6. 用 schema 重放持有者和比分。毫秒可以和 `docs/evidence/nr02/` 不同。事件名、打断那一次没有 `PointScored`、另一次 `PointScored` + `CoreReturnedToCenter`、`CoreReset` 的 `anchor` 为 `center`（关卡对象 `NR_CoreSpawn`）且比分不变，这些必须对得上。
7. 双持或同一次读条两分：三份日志原样退回。不要在 GameMode、GameState、PlayerState 或关卡蓝图里加一套计分。
